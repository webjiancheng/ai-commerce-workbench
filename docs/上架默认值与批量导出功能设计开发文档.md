# 上架默认值与批量导出功能设计开发文档

## 0. 文档目的

本文档用于指导 Codex 继续开发当前项目中的「上架默认值」与「批量导出」功能。

当前项目是一个面向跨境电商运营的本地工作台，核心链路是：

```text
浏览器插件采集商品
-> 原始数据入库 raw_products
-> 创建商品任务 product_tasks
-> AI 补全标题/类目/图片提示词
-> 图片资产管理
-> 上架默认值补齐
-> 导出 Temu 平台 Excel 模板
```

本次功能设计的重点不是重做 ERP，而是让运营可以：

1. 配置 Temu 半托上架默认值。
2. 批量生成导出字段草稿。
3. 支持用户从外部 AI 平台生成结构化模板数据后导入系统。
4. 系统动态接收字段、用户确认后写入 Temu 原始模板并导出 Excel。

## 2. 最终产品方向

本功能分为两个互补模式。

### 2.1 模式一：系统默认规则导出

适合常用模板，例如当前的 Temu 美国站半托耳饰模板。

系统负责：

1. 配置默认值规则。
2. 根据商品任务、AI 结果、图片资产生成导出草稿。
3. 校验缺失字段。
4. 写入 Excel 模板。
5. 生成导出批次。

### 2.2 模式二：外部 AI 填表结果导入导出

适合模板类目经常变化、SPU 商品属性不一致的情况。

用户流程：

```text
用户从 Temu 下载模板
-> 用户自己手动填好一个标准示例模板
-> 用户复制系统提供的固定提示词
-> 用户把“提示词 + 填好的模板示例”丢给外部 AI 平台
-> 外部 AI 返回固定 JSON
-> 用户把 JSON 粘贴回本系统
-> 系统动态接收字段
-> 系统生成导出草稿
-> 用户确认、修改、新增字段
-> 系统写入原 Temu 模板
-> 用户下载 Excel 上传 Temu
```

该模式下，系统不负责理解具体类目，不负责判断 SPU 商品属性含义，只负责接收动态字段、生成草稿、写入 Excel。

## 3. 核心设计原则

### 3.1 不把所有类目字段写死

Temu 不同类目的 SPU 商品属性不同。

例如，耳饰类目可能有：

```text
镀层
镶嵌材质
主体材质
耳针材质
风格
佩戴场合
营销节日
```

厨房用品类目可能有：

```text
材质
是否可洗碗机
适用场景
容量
套装数量
```

系统不能把这些字段全部写死。

### 3.2 系统默认规则保留

虽然支持外部 AI 动态字段，但常用字段仍然需要系统默认值能力。

例如：

```text
经营站点
发货仓
类目
运费模版
承诺发货时效
素材语言
商品产地
产地省份
币种
库存
尺寸重量
```

### 3.3 外部 AI 返回字段必须动态接收

外部 AI 返回的数据格式应以：

```text
common_fields + headers + rows
```

为核心。

系统不预设 rows 里有什么字段。

### 3.4 用户确认后再导出

不能做到：

```text
AI 返回 -> 系统直接导出
```

必须是：

```text
AI 返回 -> 系统生成草稿 -> 用户确认 -> 导出
```

### 3.5 图片、视频、详情图文不交给外部 AI

外部 AI 不负责生成或猜测图片、视频、详情图文相关字段。

这些字段如果存在于模板中，AI 只保留字段名，值返回空字符串。

后续由系统根据 product_assets、采集图、最终主图、SKU 图等资产填充。

| 字段 | 系统来源 |
|---|---|
| 商品轮播图1-英语 | product_assets.final_carousel_1 |
| 商品轮播图2-英语 | product_assets.final_carousel_2 |
| 商品轮播图3-英语 | product_assets.final_carousel_3 |
| 商品轮播图4-英语 到 商品轮播图10-英语 | 有则填，无则空 |
| SKU预览图-英语 | SKU 图；没有则用轮播图1 |
| 详情图文-英语 | 采集详情图或后续用户补充 |
| SPU主图视频 | 采集视频，有则填 |
| SPU详情视频 | 采集视频，有则填 |

轮播图规则：

1. 轮播图要求 3-10 张。
2. 前 3 张必须有。
3. 可填写素材 ID 或 URL。
4. URL 需有效且可访问。
5. 图片比例 1:1。
6. 宽高均大于 800px。
7. 图片大小 2M 内。
8. 如果素材语言选择多个语种，则每个语种分别上传对应图片。
9. 非英语语种至少需要有 1 张与英语轮播图不同。

第一期可先做字段存在性校验；图片比例、尺寸、大小、URL 可访问性可作为后续增强。

## 6. 外部 AI 填表结果导入功能设计

### 6.1 页面位置

建议放在：

```text
/exports
```

新增入口：

```text
AI填表数据导入
```

也可以做成导出中心里的一个 tab：

```text
导出中心
- 固定规则导出
- AI填表数据导入
- 导出历史
```

### 6.2 用户流程

```text
步骤1：上传 Temu 原始 Excel 模板
步骤2：复制系统固定提示词
步骤3：用户去外部 AI 平台生成 JSON
步骤4：粘贴或上传 AI 返回 JSON
步骤5：系统解析 headers、common_fields、rows
步骤6：系统生成动态草稿表
步骤7：用户确认字段和值
步骤8：用户可新增、删除、重命名、调整字段
步骤9：系统写入 Excel
步骤10：导出文件
```

### 6.3 固定提示词

系统页面提供以下提示词，允许用户一键复制。

```text
你是 Temu 平台商品上传模板结构化助手。

我会给你一个我已经手动填写好的 Temu 平台商品上传模板示例。这个示例里包含平台要求的字段、类目、SPU商品属性、SKU字段、默认值和填写格式。

你的任务：
严格按照我提供的 Temu 模板示例，提取并生成可导入系统的结构化 JSON 数据。

重要规则：

1. 字段名必须和我提供的模板示例完全一致。
2. 不允许改字段名。
3. 不允许翻译字段名。
4. 不允许合并字段。
5. 不允许删除字段。
6. 必须返回整张模板示例里的所有字段。
7. headers 必须包含模板示例中的所有字段。
8. rows 中每一行都必须包含 headers 中的所有字段。
9. 如果某个字段在示例中为空，返回空字符串 ""。
10. 所有字段值都以字符串形式返回。
11. 不要推测图片、视频、详情图文相关字段。
12. 以下字段如果存在，请保留字段名，但字段值统一返回空字符串：
   - SKU预览图-英语
   - 商品轮播图1-英语
   - 商品轮播图2-英语
   - 商品轮播图3-英语
   - 商品轮播图4-英语
   - 商品轮播图5-英语
   - 商品轮播图6-英语
   - 商品轮播图7-英语
   - 商品轮播图8-英语
   - 商品轮播图9-英语
   - 商品轮播图10-英语
   - 详情图文-英语
   - SPU主图视频
   - SPU详情视频
13. 如果模板里还有其他图片、视频、详情图文字段，也只保留字段名，字段值返回空字符串。
14. 不要自行补充模板里没有的字段。
15. 不要返回解释文字。
16. 不要使用 Markdown。
17. 不要把 JSON 包在代码块里。
18. 只返回一个合法 JSON 对象。

返回格式必须严格如下：

{
  "version": "1.0",
  "source": "external_ai_template_example",
  "sheet_name": "",
  "common_fields": {
    "经营站点": "",
    "发货仓": "",
    "类目": "",
    "运费模版": "",
    "承诺发货时效": "",
    "素材语言": ""
  },
  "headers": [],
  "rows": [],
  "warnings": []
}

字段说明：

1. version 固定返回 "1.0"。
2. source 固定返回 "external_ai_template_example"。
3. sheet_name 返回模板工作表名称；如果无法判断，返回空字符串。
4. common_fields 返回模板顶部公共字段。
5. headers 返回模板示例里的所有商品明细字段名，顺序必须尽量保持和模板一致。
6. rows 返回模板示例里的商品明细行数据。
7. warnings 返回你发现的问题；没有问题返回空数组 []。

处理 rows 时必须遵守：

1. 每一行都必须是一个 JSON 对象。
2. 每一行的 key 必须和 headers 中的字段名一致。
3. 如果 headers 中有字段，但该行没有值，填 ""。
4. 如果示例里有多行商品或 SKU，就按示例行数返回多行。
5. 不要把 common_fields 混入 rows。
6. 不要把说明文字、字段注释、表头备注放进 rows。
7. 不要返回 Excel 单元格坐标。
8. 不要返回公式。
9. 不要返回图片文件本身。
10. 不要返回视频文件本身。

现在请根据我提供的 Temu 模板示例，返回结构化 JSON。
```

```json
      "商品轮播图2-英语": "",
      "商品轮播图3-英语": ""
    }
  ],
  "warnings": []
}
```

### 6.5 系统解析规则

系统接收 JSON 后：

1. 校验 JSON 合法性。
2. 校验 version 是否存在。
3. 校验 headers 是否为数组。
4. 校验 rows 是否为数组。
5. 校验每个 row 是否为对象。
6. headers 为空则拒绝导入。
7. rows 为空则拒绝导入。
8. row 中缺少 header 字段时自动补空字符串。
9. row 中出现 headers 外字段时，加入额外字段，提示用户确认是否加入 headers。
10. headers 中重复字段时提示用户处理。
11. common_fields 中字段可以写入模板顶部区域。
12. warnings 原样展示给用户。

### 6.6 草稿字段操作

导入后进入字段确认页面。

用户可以：

| 操作 | 说明 |
|---|---|
| 新增字段 | 新增一列 |
| 删除字段 | 删除一列 |
| 重命名字段 | 改列名 |
| 调整字段顺序 | 拖拽列顺序 |
| 批量填充列 | 给整列填同一个值 |
| 批量清空列 | 清空整列 |
| 单元格编辑 | 修改某个值 |
| 字段是否导出 | 控制该字段是否写入 Excel |
| 额外字段加入 headers | 将 row 里出现但 headers 不包含的字段加入正式字段 |

## 11. Excel 写入规则

### 11.1 固定规则导出

走当前 export_runner 逻辑，按模板字段映射写入。

### 11.2 AI 导入导出

需要一个新的 service，例如：

```text
apps/api/app/services/ai_template_import.py
apps/api/app/services/ai_template_export.py
```

核心函数建议：

```python
parse_external_ai_json(raw_json_text: str) -> ParsedAIImport
normalize_ai_rows(headers: list[str], rows: list[dict]) -> list[dict]
validate_ai_import(headers: list[str], rows: list[dict], common_fields: dict) -> ValidationResult
export_ai_import_to_excel(template_path: str, common_fields: dict, headers: list[str], rows: list[dict], field_settings: dict) -> str
```

### 11.3 查找 Excel 表头

AI 导入模式下，仍需要在 Excel 中找到明细表头行。

建议逻辑：

1. 优先使用默认配置，例如 header_row=4，data_start_row=6。
2. 如果找不到，扫描前 20 行，寻找与 headers 重合度最高的一行。
3. 匹配度最高行作为 header_row。
4. data_start_row = header_row + 2 或根据模板实际结构设置。
5. 如果无法确定，返回错误，让用户手动选择表头行。

第一期可先使用 Temu 模板默认结构：

```text
公共字段：第 1-2 行
商品字段表头：第 4 行
数据开始行：第 6 行
```

具体行号需以当前项目已有 export_runner 实现为准。

### 11.4 公共字段写入

需要支持这些字段：

```text
经营站点
发货仓
类目
运费模版
承诺发货时效
素材语言
```

写入方式：

1. 扫描前几行，找到同名单元格。
2. 将值写入右侧单元格或下一行对应位置。
3. 如果找不到，记录 warning，不阻断导出。

## 15. 与之前方案相比，需要改动的点

### 15.1 不再要求系统识别所有类目模板

旧想法：

```text
系统上传模板 -> 系统识别字段/必填/下拉值
```

新方案：

```text
用户用填好的模板示例教外部 AI -> 外部 AI 返回 headers/rows -> 系统动态接收
```

因此不需要做复杂模板解析器。

### 15.2 外部 AI 返回整张模板字段

旧想法：

```text
AI 只返回类目 + SPU商品属性
```

新方案：

```text
AI 返回整个模板示例里的所有字段
```

headers 和 rows 全动态。

### 15.3 图片视频字段不由外部 AI 填

旧提示词包含图片 URL、商品资料等描述，容易让 AI 乱编。

新提示词明确：

```text
图片、视频、详情图文字段保留字段名，值统一空字符串。
```

后续由系统补图。

### 15.4 用户可添加模板字段

导入草稿支持：

```text
新增字段
删除字段
重命名字段
字段是否导出
```

如果新增字段不在原模板里，默认不导出；用户强制开启后追加到 Excel 末尾。

## 16. Codex 开发注意事项

1. 不要把 AI 导入模式做成固定字段表单。
2. rows 必须支持任意字段。
3. headers 顺序很重要，前端表格和导出都要尽量保持顺序。
4. 不要让外部 AI 返回的 JSON 直接覆盖原模板。
5. 必须先生成草稿，用户确认后再导出。
6. Excel 写入要尽量保留原模板格式。
7. 新增字段默认不写入 Excel，除非用户开启 export=true。
8. common_fields 和 rows 分开处理。
9. 图片、视频、详情图文先不由外部 AI 填。
10. 第一版校验保持轻量，重点保证能导入、能编辑、能导出。
11. 固定规则导出和 AI 导入导出是两个模式，不要互相阻塞。
12. 后续可以把默认值规则用于 AI 导入草稿的批量补值，但第一期不是必须。

## 18. 第一版验收标准

### 18.1 AI 导入

1. 用户可以上传 xlsx 模板。
2. 用户可以复制固定提示词。
3. 用户可以粘贴 AI 返回 JSON。
4. 系统可以解析 common_fields、headers、rows。
5. 系统可以展示动态表格。
6. 用户可以编辑单元格。
7. 用户可以新增字段。
8. 用户可以删除字段。
9. 用户可以设置字段是否导出。
10. 系统可以保存草稿。
11. 系统可以导出 Excel。
12. 导出的 Excel 保留原模板基本格式。
13. 导出历史能看到该次记录。

### 18.2 默认值规则

1. 可以创建 Temu 美国站半托耳饰默认规则。
2. 可以编辑公共字段默认值。
3. 可以编辑商品基础默认值。
4. 可以编辑饰品属性默认值。
5. 可以编辑 SKU、库存、尺寸重量默认值。
6. 可以保存 values_json。
7. 可以启用/停用规则。

### 18.3 批量导出

1. 可以选择任务。
2. 可以选择默认规则。
3. 可以生成导出草稿。
4. 可以校验缺失字段。
5. 可以导出 Excel。
6. 可以查看导出历史。

---

## 19. 后续增强

1. AI 导入模式支持从系统商品任务批量补图。
2. AI 导入草稿支持按默认规则批量补值。
3. 支持图片 URL 有效性校验。
4. 支持图片尺寸、比例、大小校验。
5. 支持模板字段差异对比。
6. 支持多语言素材图片。
7. 支持用户保存某次 AI 导入字段结构为模板。
8. 支持把 AI 导入草稿转成可复用默认规则。
9. 支持 SKU 多行合并预览。
10. 支持导出失败原因定位。
