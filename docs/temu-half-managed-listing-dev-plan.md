# Temu 美国站半托饰品上架默认值与批量导出开发计划

## 1. 当前决策

第一期只支持一个真实业务场景：

```text
平台：Temu
履约：半托
站点：美国站
类目：饰品当前类目
模板：商品上传模版.xlsx / 模版 表
```

第一期不做通用多模板管理，也不让用户选择或理解 `template_id`。系统内部可以读取固定模板文件结构，但数据库不保留 Excel 模板记录。后续如果接入别的模板，例如 `妙手Temu导入模板-非服饰类模板 .xlsx`，按新模板结构单独适配。

数据库可以保留“类目字段方案”，用于保存不同类目的 SPU 商品属性字段、默认值、枚举提示和上架台提示。这个概念不要再叫“模板记录”，更适合叫：

```text
category_listing_profiles
或沿用现有 listing_templates 表但产品命名改成「类目字段方案」
```

## 2. 目标流程

### 2.1 上架台主流程

```text
原始采集数据
-> 创建商品任务
-> AI 生成标题/类目/图片提示词/图片资产
-> 上架台抽屉选择上架默认值
-> 用户补充或修改 SPU 属性、SKU、价格、库存、尺寸重量
-> 导出检查
-> 批量导出 商品上传模版.xlsx
```

### 2.2 AI 填表导入流程

系统不调用 AI 解析 Excel，避免 token 成本和不稳定性。

```text
系统提供固定提示词和 JSON 格式
-> 用户去外部 AI 工具生成 JSON
-> 用户粘贴 JSON
-> 系统解析 common_fields + headers + rows
-> 系统补默认值
-> 用户确认草稿
-> 导出检查
-> 回写商品上传模版.xlsx
```

## 3. 现有可复用模块

### 3.1 可以直接复用

- `default_rules`
  - 已有规则增删改查。
  - 适合继续保存“上架默认值”。
  - 第一阶段继续使用 `values_json` 保存字段默认值。

- `export_field_drafts`
  - 已有单任务导出草稿。
  - 适合保存上架台抽屉里用户对单个商品的覆盖值。
  - 需要把字段名收敛到 `商品上传模版.xlsx / 模版` 的中文字段。

- `ai_import_batches / ai_import_drafts`
  - 已有外部 AI JSON 导入草稿结构。
  - 适合继续做 AI 填表导入。
  - 需要移除“上传模板后系统解析给 AI”的强依赖，改成固定提示词 + 用户粘贴 JSON。

- `product_assets`
  - 已经保存 `width / height / public_url / selected_for_export`。
  - 可用于图片尺寸、比例、必填检查。

- `product-tasks` 抽屉里的 `defaults` tab
  - 已有上架默认值/人工补字段入口。
  - 已支持动态添加商品属性、SKU、敏感属性。
  - 这是第一期主入口，应该继续增强，不另开一个重复页面。

- `/exports`
  - 已有固定导出、AI 导入、导出历史三个方向。
  - 第一阶段保留，但导出中心更多承担“历史、下载、失败批次复查”，不是主要编辑入口。

### 3.2 可复用但需要改名或降级

- `listing_templates`
  - 当前表名和接口像“上架模板”，容易和 Excel 模板混淆。
  - 不建议物理删除。
  - 建议产品语义改成“类目字段方案”。
  - 后续只保存不同类目的 SPU 商品属性字段、默认值、字段提示、排序，不保存 Excel 文件记录。

- `export_templates / export_field_mappings`
  - 当前用于 `妙手Temu导入模板-非服饰类模板 .xlsx / Sheet1` 的字段映射。
  - 第一阶段不作为用户可见功能。
  - 如果继续保留，要内部化，不在 UI 中展示模板选择。
  - `商品上传模版.xlsx / 模版` 的导出最好走固定解析/固定写入逻辑，避免继续套旧 Sheet1 映射。

## 4. 需要重点优化的地方

### 4.1 字段体系统一

当前代码里混用了两套字段：

```text
旧非服饰模板字段：
申报价CNY
建议售价CNY
库存
产品轮播图

商品上传模版.xlsx 字段：
申报价格-美国站
发货仓1库存
商品轮播图1
SKU预览图-英语
```

第一阶段必须统一到 `商品上传模版.xlsx / 模版` 的中文字段名。导出草稿、默认值、抽屉表单、AI 导入草稿、导出检查都使用同一套字段名。

### 4.2 固定模板解析

新增一个内部模板结构解析服务，读取固定文件：

```text
商品上传模版.xlsx
sheet: 模版
公共字段行：1
公共默认值行：2
明细字段行：4
提示行：5
数据起始行：6
```

解析结果只用于运行时字段定义，不写入数据库模板表。

需要解析：

- 公共字段
- 明细字段 132 列
- 必填字段
- 条件必填字段
- 枚举字段
- 条件必填规则
- 字段分组

### 4.3 上架默认值页面

`/rules` 保留，但第一期只围绕当前 Temu 半托饰品类目。

页面需要支持：

- 创建/编辑一套默认值规则。
- 选择类目字段方案。
- 配置公共字段默认值。
- 配置通用字段默认值。
- 配置 SPU 商品属性默认值。
- 动态添加 SPU 属性字段。
- 复制规则。
- 停用规则。

不需要支持：

- 让用户上传或管理 Excel 模板。
- 暴露 `template_id`。
- 面向多平台多模板做复杂筛选。

### 4.4 上架台抽屉

上架台抽屉是用户实际补字段的主位置。

建议把 `defaults` tab 调整为以下分组：

```text
导出检查摘要
默认值规则选择
基础信息
SPU 商品属性
SKU 规格与销售
尺寸重量
图片视频
动态字段
```

抽屉必须支持：

- 选择上架默认值规则。
- 应用默认值到当前商品。
- 修改类目 SPU 属性。
- 动态添加字段。
- 修改 SKU 分类、SKU 数量、SKU 数量单位、是否独立包装。
- 修改申报价格、库存、尺寸重量。
- 显示字段来源：默认值 / AI / 商品任务 / 图片资产 / 人工。
- 显示导出检查错误，并能定位字段。

### 4.5 导出检查

导出检查保留，并前移到上架台抽屉。

阻断错误：

- 模板必填字段为空。
- `商品层级` 为空或不合法。
- `SPU货号` 为空。
- `SKU货号` 为空。
- `申报价格-美国站` 为空。
- `发货仓1` 为空。
- `发货仓1库存` 为空。
- `SKU预览图-英语` 为空。
- `商品轮播图1/2/3` 为空。
- 枚举字段值不在模板枚举中。

警告：

- 条件必填字段为空。
- 图片宽高低于 800px。
- 图片比例不是 1:1。
- 图片大小未知或超过限制。
- 详情图文为空。
- 视频为空。
- AI 标题或类目结果缺失。

图片检查第一期可以利用 `product_assets.width / height` 和本地文件大小。远程 URL 可访问性可以先做警告，不作为强阻断。

### 4.6 批量导出

批量导出应允许部分成功。

推荐交互：

```text
勾选任务
-> 批量导出检查
-> 显示通过/失败数量
-> 用户选择：
   只导出通过的任务
   返回修正失败任务
```

不要因为一个任务失败就阻止所有任务导出。

导出历史继续使用 `export_batches / export_records`。

## 5. 建议收敛或停用的地方

这里不建议做物理删除，避免破坏已有链路。建议先停用入口或改名。

### 5.1 不建议继续扩展 `export_templates` UI

原因：

- 当前第一期不需要用户管理 Excel 模板。
- 用户关心的是当前 Temu 半托饰品上架，不关心 `template_id`。
- 继续暴露模板管理会让流程变复杂。

处理建议：

- 保留后端表和接口。
- 前端 `/exports` 暂不突出模板选择。
- 后续多模板稳定后再恢复。

### 5.2 `listing_templates` 不作为 Excel 模板

原因：

- 用户明确要求数据库不保留模板记录。
- 但系统确实需要保留不同类目的 SPU 商品属性字段。

处理建议：

- 不删除表。
- 改产品命名为“类目字段方案”。
- 字段内容只保存类目属性，不保存 Excel 文件路径。

### 5.3 `listing_default_fields.py` 需要降级为种子/参考

原因：

- 里面硬编码了不少字段和选项。
- 第一阶段应以 `商品上传模版.xlsx / 模版` 解析结果为准。

处理建议：

- 保留作为内置默认值参考。
- 不再作为最终字段权威来源。

### 5.4 旧字段映射需要迁移

需要把以下旧字段从上架台与导出草稿中迁移或兼容：

```text
申报价CNY -> 申报价格-美国站
库存 -> 发货仓1库存
建议售价CNY -> 制造商建议零售价(USD) 或暂不导出
产品轮播图 -> 商品轮播图1~商品轮播图10
```

## 6. 分阶段开发计划

### 阶段 1：字段标准化与模板解析

目标：让系统以 `商品上传模版.xlsx / 模版` 为唯一字段标准。

任务：

- 新增固定模板解析服务。
- 输出公共字段、明细字段、必填、条件必填、枚举、分组。
- 把上架默认值、导出草稿、导出检查统一到模板中文字段。
- 梳理旧字段兼容映射。

验收：

- 系统能读取 132 个明细字段。
- 能识别 28 个必填字段和 41 个条件必填字段。
- 上架台保存字段时使用新字段名。

### 阶段 2：上架默认值规则改造

目标：默认值规则服务于当前 Temu 半托饰品类目。

任务：

- `/rules` 页面收敛成当前类目默认值配置。
- 支持动态 SPU 属性字段。
- 默认值规则可在上架台选择。
- 应用默认值时保留人工覆盖字段。

验收：

- 用户能配置一套 `Temu美国站半托饰品默认值`。
- 上架台可选择并应用该规则。
- 应用后生成/刷新 `export_field_drafts`。

### 阶段 3：上架台抽屉增强

目标：用户在抽屉里完成导出前补字段。

任务：

- 重构 `defaults` tab 分组。
- 加入规则选择。
- 支持 SPU 属性动态添加和删除。
- 支持 SKU 行编辑。
- 支持申报价格、库存、尺寸重量编辑。
- 展示字段来源。
- 展示导出检查错误。

验收：

- 用户不离开上架台即可补齐导出字段。
- 错误字段能直接在抽屉里看到。

### 阶段 4：导出检查统一

目标：固定导出和 AI 导入使用同一套检查结果格式。

任务：

- 统一 validation result 结构。
- 增加图片尺寸、比例、大小检查。
- 增加模板枚举检查。
- 增加 SPU/SKU 关系检查。
- 上架台批量检查显示通过/失败任务。

验收：

- 有阻断错误时不能导出该任务。
- 只有警告时允许继续导出。
- 批量检查结果能定位到任务和字段。

### 阶段 5：批量导出

目标：支持部分成功导出。

任务：

- 批量导出前自动执行导出检查。
- 支持只导出通过任务。
- 失败任务写入 `export_records` 或返回结构化失败原因。
- 导出历史展示成功数、失败数、SKU 行数、下载链接。

验收：

- 20 个任务中 17 个通过时，可导出 17 个。
- 失败 3 个保留清晰原因。

### 阶段 6：AI 填表导入收敛

目标：外部 AI JSON 导入，不由系统消耗 token 解析模板。

任务：

- 页面提供固定提示词。
- 粘贴 JSON 后解析 `common_fields / headers / rows`。
- 用默认值规则补齐空字段。
- 用户确认草稿。
- 使用同一套导出检查。
- 回写 `商品上传模版.xlsx / 模版`。

验收：

- 用户可用外部 AI 生成 JSON。
- 系统可导入、补默认值、检查、导出。

## 7. 后续导出适配器方案

### 7.1 为什么需要适配器

第一期主线以 `商品上传模版.xlsx / 模版` 为准，但后续可能需要导出到其他格式，例如：

```text
妙手Temu导入模板-非服饰类模板 .xlsx / Sheet1
```

这些模板字段名、表头行、图片字段结构、必填规则都不一样。如果把上架台字段直接绑定到某一个 Excel 模板，后续每换一个模板都要重做上架台和默认值规则。

因此推荐采用：

```text
上架台维护标准业务字段
-> 导出适配器转换
-> 写入目标 Excel 模板
```

用户看到的是“导出格式”，不是 `template_id`。

### 7.2 标准业务字段层

导出草稿 `export_field_drafts.fields_json` 第一阶段应逐步收敛成标准业务字段。字段以当前 `商品上传模版.xlsx / 模版` 的中文字段为主，因为它最贴近 Temu 半托官方类目模板。

示例：

```text
商品层级
SPU货号
商品名称
英文名称
商品产地
产地省份
镀层
镶嵌材质
主体材质
SKU货号
规格类型1
规格1内容
申报价格-美国站
币种
发货仓1
发货仓1库存
SKU预览图-英语
商品轮播图1
商品轮播图2
商品轮播图3
详情图文-英语
主图视频
详情视频
```

这层字段由以下来源共同补齐：

- 默认值规则。
- 商品任务和 AI 标题/类目。
- 上架台抽屉人工编辑。
- 商品图片资产。
- 外部 AI 导入草稿。

### 7.3 适配器职责

每个导出适配器负责把标准业务字段转换为目标 Excel。

适配器应包含：

```text
adapter_key             导出格式标识
display_name            给用户看的导出格式名称
template_file_path      目标 Excel 文件路径或内置文件名
sheet_name              目标 sheet
header_config           表头、提示行、数据起始行
field_mapping           标准字段 -> 目标字段
validation_rules        目标格式专属校验
write_strategy          写入方式
```

第一期可以代码内置，不需要数据库保存 Excel 模板记录。

推荐内置两个 key：

```text
temu_half_managed_jewelry_upload
miaoshou_temu_non_apparel
```

### 7.4 商品上传模板适配器

适配器：

```text
adapter_key: temu_half_managed_jewelry_upload
display_name: Temu美国站半托饰品商品上传模板
file: 商品上传模版.xlsx
sheet: 模版
```

写入规则：

- 公共字段写入第 2 行。
- 明细字段从第 6 行开始写。
- 字段以第 4 行中文表头匹配。
- 图片字段按 `商品轮播图1~商品轮播图10`、`SKU预览图-英语`、`详情图文-英语` 写入。
- 枚举、必填、条件必填从隐藏表和提示行解析。

这是第一期默认导出格式。

### 7.5 妙手模板适配器

适配器：

```text
adapter_key: miaoshou_temu_non_apparel
display_name: 妙手Temu非服饰导入模板

```

目标：复用同一份上架台草稿，导出成妙手模板。

典型字段映射示例：

```text
商品名称 -> 产品标题 / 商品标题
英文名称 -> 英文标题
类目 -> 类目ID 或 类目字段
SPU货号 -> 主编号 / 主货号
SKU货号 -> 平台SKU 或 SKU货号
规格类型1 -> 规格名称1
规格1内容 -> 规格属性值1
规格类型2 -> 规格名称2
规格2内容 -> 规格属性值2
申报价格-美国站 -> 申报价（CNY）

最长边（cm） -> 长（cm）

```

注意：上面是方向示例，实际字段名要以 `妙手Temu导入模板-非服饰类模板 .xlsx / Sheet1` 的真实表头为准。

### 7.6 用户界面

批量导出时显示“导出格式”：

```text
导出格式：
[Temu美国站半托饰品商品上传模板]
[妙手Temu非服饰导入模板]
```

默认选择 `Temu美国站半托饰品商品上传模板`。

用户不需要看到：

```text
template_id
adapter_key
Excel 文件路径
字段映射表
```

这些都属于系统内部。

### 7.7 校验策略

导出检查分两层：

1. 标准业务字段检查。
   - 例如标题、SKU、价格、库存、图片是否齐全。

2. 适配器专属检查。
   - 例如妙手模板是否要求某个字段名、某种图片合并格式、某个枚举值。

如果同一批任务导出到不同格式，检查结果也应该按格式区分。

示例：

```text
任务 #12
Temu商品上传模板：通过
妙手非服饰模板：缺少 类目ID
```

### 7.8 存储策略

第一阶段和第二阶段都不需要把 Excel 模板文件作为数据库模板记录保存。

可以保存的是：

- 导出批次使用的 `adapter_key`。
- 导出批次显示名。
- 导出文件路径。
- 校验结果。
- 字段映射快照，可选。

建议 `export_batches.export_mode` 或新增字段记录：

```text
export_adapter: temu_half_managed_jewelry_upload
export_adapter_name: Temu美国站半托饰品商品上传模板
```

如果不想改表，第一阶段也可以把这些写入 `export_records.validation_result_json` 或批次扩展 JSON，后续再规范化。

### 7.9 开发顺序

适配器不要影响第一期主链路。建议顺序：

1. 先完成 `temu_half_managed_jewelry_upload`。
2. 把导出逻辑整理成适配器接口。
3. 再接 `miaoshou_temu_non_apparel`。
4. 最后再考虑用户自定义导出格式。

### 7.10 不建议的做法

- 不要让上架台同时维护两套字段。
- 不要把妙手模板字段直接塞进上架默认值主表单。
- 不要为了妙手模板改掉第一期标准字段。
- 不要让用户理解 `template_id` 或字段映射细节。
- 不要在第一期做用户自定义 Excel 映射编辑器。

## 8. 第一阶段不做的事

- 不做通用多模板管理。
- 不让用户选择或理解 `template_id`。
- 不把 Excel 模板文件保存成数据库模板记录。
- 不让系统调用 AI 去解析 Excel。
- 不物理删除现有表和接口。
- 不批量删除任何文件或目录。

## 9. 开发顺序建议

建议按这个顺序做，风险最低：

1. 固定模板解析服务。
2. 字段名兼容映射。
3. 上架台抽屉字段保存改造。
4. 默认值规则选择和应用。
5. 导出检查。
6. 批量导出部分成功。
7. AI 填表导入收敛。
8. 导出适配器接口整理。
9. 妙手 Temu 非服饰模板适配器。

这样可以先把主链路跑通，再处理导入和历史能力。
