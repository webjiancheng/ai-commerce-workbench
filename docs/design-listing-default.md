> 目标类目：服装、鞋靴和珠宝饰品 > 女士时尚 > 女士饰品 > 女士耳饰 > 女士时尚耳廓环和全耳式耳环
> 当前类目：女士耳饰（半托 Temu 美国站）
> 状态：设计方案，待确认后实现

## 一、字段分层体系

把上架模板的所有字段按用户操作频率分为 4 层，让用户**尽可能少操作**：

| 分层 | 说明 | 用户操作 | 示例字段 |
|------|------|---------|---------|
| **Layer-1 系统自动** | 由商品任务 / 图片资产自动填充 | ❌ 不需要 | 商品名称、英文名称、轮播图、视频 |
| **Layer-2 统一默认** | 所有类目通用，选类目后自动填充 | ⚙️ 可改但不需改 | 经营站点、发货仓、尺寸重量、SKU分类 |
| **Layer-3 类目属性** | 不同类目有不同的属性值 | ✏️ 手动选择 | 镀层、镶嵌材质、主体材质、风格 |
| **Layer-4 人工填写** | 必须人工输入 | ✏️ 必须填 | 申报价格、参考链接、规格内容 |

## 三、AI 填表导入功能设计

### 3.1 完整流程

```
用户操作                                系统行为
───────────────────────────────────    ──────────────────────────────────────
1. 选择类目
   └── 女士时尚>女士饰品>女士耳饰        系统显示该类目对应的字段要求

2. 下载 Temu 类目模板
   └── 点击「下载模板」按钮              系统读取类目字段定义，生成模板 Excel
                                        列头 = 该类目需要的全部字段
                                        第一行 = 示例数据（来自默认规则）

3. 复制系统提示词
   └── 点击「复制提示词」按钮            复制提示词到剪贴板
                                        提示词内容：让外部 AI 读取 Excel 并返回 JSON

4. 把填好的模板丢给外部 AI
   └── 用户打开 ChatGPT/Claude          外部 AI 读取模板内容，返回 headers + rows JSON
                                        参考提示词告诉 AI 返回格式

5. 把 AI 返回结果粘贴到系统
   └── 粘贴 JSON 到文本框               系统接收用户粘贴的 JSON
                                        点击「解析并处理」

6. 系统解析并处理
   ├── 解析 headers + rows              读取所有字段名和数据行
   ├── 字段分类                          按字段分类体系分配到对应层
   ├── 系统默认值补齐空字段               Layer-2/Layer-3 自动填充
   ├── 商品任务/图片资产补齐图片字段      Layer-1 自动填充
   └── 生成导出草稿                      存入 ai_import_drafts

7. 用户检查草稿
   ├── 查看自动填充字段                  确认默认值是否正确
   ├── 查看 AI 返回的原始字段            确认 AI 是否正确识别
   ├── 查看缺失字段                      人工补充申报价格等
   └── 修改/调整字段值                   人工修改任意字段

8. 导出 Excel
   └── 点击「导出 Excel」                最终确认后导出上架模板
```

### 3.3 字段分类策略

当 AI 返回 headers + rows 时，系统按以下策略分类：

| 分类 | 说明 | 处理方式 |
|------|------|---------|
| `auto_fill` | 系统自动填充字段 | 用户不可编辑，直接从资产填充 |
| `uniform_default` | 统一默认字段 | 自动用规则默认值填充，用户可改 |
| `category_specific` | 类目特定属性 | 自动用类目默认值填充，用户可改 |
| `manual_required` | 人工必填字段 | 标红提示用户人工填写 |
| `asset_fill` | 从资产补齐 | 系统从商品资产自动填充 |
| `custom` | AI 自定义字段 | 系统自动添加为新字段，允许用户编辑 |

## 九、产品评审后的前端优化方案（全屏高密度版）

> 本节是结合当前项目真实页面、`商品上传模版.xlsx` 结构和运营使用场景后的修订建议。
> 核心原则：**占满全屏、省空间、少跳转、问题优先、默认值一键补齐**。

### 9.1 前端入口收敛

不建议新增独立 `/ai-import` 页面，原因：

1. 当前 `/exports` 已经有 AI 填表导入能力。
2. 独立页面会让运营在“导出中心”和“AI 导入”之间来回找入口。
3. AI 导入最终目标仍然是导出 Excel，应放在导出中心里。

建议保留两个主页面：

| 页面 | 定位 | 处理内容 |
|------|------|----------|
| `/rules` | 上架默认值规则 | 配置站点、仓库、物流、SKU 默认、类目属性默认 |
| `/exports` | 导出中心 | 固定规则导出、AI 填表导入、草稿检查、Excel 导出 |

商品任务页只保留轻入口：

- 查看当前任务导出字段草稿。
- 手动补单个任务字段。
- 查看图片资产是否满足导出要求。

### 9.2 `/rules` 页面：全屏高密度默认值规则工作台

页面目标：让运营快速维护“以后批量上架都会重复使用的默认值”，不要让用户逐列理解 Temu 132 个字段。

#### 9.2.1 布局

│ 左侧规则列表   │ 中间规则编辑区                                │ 右侧校验预览   │
│ 260px          │ 自适应占满                                    │ 320px          │
│               │                                              │               │
│ 快速模板       │ 基础信息                                      │ 覆盖率          │
│ - 女士耳饰     │ 平台 / 站点 / 履约 / 类目 / 优先级             │ 必填缺失        │
│ - 女童耳饰     │                                              │ 冲突字段        │
│ - 女士项链     │ 经营配置                                      │ 人工字段        │
│               │ 站点 / 仓库 / 类目 / 运费 / 时效 / 语言         │               │

#### 9.2.2 省空间规则

- 页面使用 `100vh`，顶部工具条固定高度，主体区域内部滚动。
- 左侧规则列表固定宽度，避免列表挤压编辑区。
- 中间编辑区使用双列或三列紧凑表单，不使用大卡片堆叠。
- 右侧预览固定宽度，只显示摘要和问题，不展开全部字段。
- 字段组默认折叠，只展开“经营配置”和“商品与 SKU 默认”。
- 每个字段一行高度控制在 36-40px。
- 文案短句化，不放大段说明；复杂说明放到 hover tooltip。

#### 9.2.3 字段分组

默认值页面只维护“适合复用”的字段：

| 分组 | 字段 | 说明 |
|------|------|------|
| 经营配置 | 经营站点、发货仓、类目、运费模版、承诺发货时效、素材语言 | 对应模板第 1-2 行公共配置，不是商品明细行字段 |
| 商品基础 | 商品产地、产地省份、商品层级、SPU货号规则、SKU货号规则 | 货号规则是生成策略，不直接写入模板 |
| SKU 默认 | 币种、发货仓1、默认库存、SKU分类、SKU数量、SKU数量单位、是否独立包装 | 批量重复最多，优先做默认 |
| 尺寸重量 | 最长边（cm）、次长边（cm）、最短边（cm）、重量（g） | 必须使用模板真实字段名保存 |
| 敏感属性 | 敏感词属性1-7、液体容量（ml）、刀具长度(cm)、刀尖角度(度)、储电容量（wh） | 默认空，用户按类目/商品补 |
| 类目属性 | 镀层、镶嵌材质、主体材质、耳针材质、风格、佩戴场合、营销节日、主题、金属部件材质 | 按类目显示 |

不建议在默认值页面直接维护：

- 商品名称、英文名称：来自 AI 或商品任务。
- SPU货号、SKU货号：来自生成规则或任务。
- 商品轮播图、SKU预览图、详情图文、主图视频、详情视频：来自图片资产或素材 URL。
- 申报价格-美国站：可以给建议值，但必须提示人工确认。
- 规格1内容、规格2内容：来自 SKU 数据或外部 AI，不应作为类目默认值写死。

#### 9.2.4 右侧预览

右侧不要展示完整 132 列，展示运营决策需要的信息：

| 缺失/错误 | 红色边框 |

字段来源必须能解释，否则运营无法判断系统为什么填了某个值。

### 9.4 真实模板适配要求

`商品上传模版.xlsx` 的真实结构需要作为前端和后端的字段依据：

1. `模版` sheet 第 1 行是公共配置字段。
2. `模版` sheet 第 2 行是公共配置默认值。
3. `模版` sheet 第 4 行是商品明细字段表头。
4. `模版` sheet 第 5 行是字段必填/条件必填说明。
5. `HeaderKeyMap` 是模板字段内部 key 映射。
6. `KeyValueMap` 和相关 sheet 是下拉值/枚举来源。

因此前端展示名可以做简化，但保存和导出必须使用模板真实字段名：

| 运营展示 | 保存字段 |
|----------|----------|
| 最长边 | 最长边（cm） |
| 次长边 | 次长边（cm） |
| 最短边 | 最短边（cm） |
| 重量 | 重量（g） |
| 轮播图1 | 商品轮播图1 |
| 主图视频 | 主图视频 |
| 详情视频 | 详情视频 |

### 9.7 AI 填表导入提示词升级版

当前提示词不能只要求外部 AI 返回 `headers + rows`，否则容易出现字段漏传、字段改名、SPU/SKU 层级错误、图片字段乱填描述、JSON 带解释文字等问题。

前端应根据当前上传的 Temu 模板、选中的默认值规则、类目和用户选择动态生成提示词。

#### 9.7.1 提示词生成原则

1. 字段名必须来自模板真实表头，不能手写简化字段。
2. 公共字段和商品明细字段必须分开。
3. 明确禁止 AI 改字段名、删字段、翻译字段、合并字段。
4. 明确图片/视频字段只能填素材 ID 或 URL，没有就留空。
5. 明确申报价格不能编造，没有可靠价格就留空。
6. 明确多 SKU 商品必须拆成 SPU 行 + SKU 行。
7. 明确返回纯 JSON，不能带 Markdown、解释文字或代码块。
8. 默认值只作为参考，系统后续还会二次补齐，AI 不确定时应留空。

#### 9.7.2 前端动态拼接内容

提示词不应该写死，应由前端或后端动态拼接以下部分：

| 区块 | 来源 | 用途 |
|------|------|------|
| 模板公共字段 | `模版` sheet 第 1 行 | 生成 `common_fields` |
| 商品明细 headers | `模版` sheet 第 4 行 | 生成 `headers`，顺序必须一致 |
| 字段必填说明 | `模版` sheet 第 5 行 | 提醒 AI 必填/条件必填 |
| 默认值规则 | 当前选中的 `default_rules.values_json` | 给 AI 参考，系统后续也会补齐 |
| 类目信息 | 当前模板第 2 行或用户选择类目 | 防止 AI 误填其他类目属性 |
| 行结构规则 | 固定系统说明 | 约束 SPU/SKU 拆行 |
| 输出 JSON schema | 固定系统说明 | 确保系统可解析 |

#### 9.7.3 推荐提示词模板

```text
你是 Temu 商品上传模板数据整理助手。

你的任务：
根据用户提供的 Temu 商品上传模板、商品资料、图片信息和规格信息，生成系统可直接导入的 JSON。

重要规则，必须严格遵守：

1. 只能返回 JSON，不要返回解释、Markdown、代码块或多余文字。
2. 字段名必须和模板字段完全一致，不能改名、翻译、合并、拆分或删减。
3. headers 必须包含【商品明细字段】中的全部字段，顺序必须保持一致。
4. common_fields 只放【模板公共字段】。
5. rows 只放商品明细字段，不要把 common_fields 重复塞进每一行。
6. 如果某个字段没有可靠信息，请填空字符串 ""，不要猜。
7. 图片和视频字段如果没有素材 ID 或可访问 URL，请填空字符串 ""。
8. 图片和视频字段禁止填写“见附件”“产品图”“主图”“详情图”等描述文字。
9. 商品名称、英文名称要适合 Temu 上架，不要包含侵权品牌词、平台词、夸大词。
10. 申报价格-美国站如果无法确定，请填空字符串 ""，不要编造。
11. 尺寸重量字段只填数字，不要带单位。
12. 敏感属性无可靠信息时保持空，不要默认填写敏感品。
13. 只使用模板允许的字段，不要自创字段。
14. 如果发现无法判断或有风险的信息，写入 warnings。

SPU/SKU 行结构规则：

1. 单 SKU 商品：
   - 只生成一行。
   - 商品层级填 “单SKU商品”。
   - SPU货号和 SKU货号都要填写。

2. 多 SKU 商品：
   - 第一行是 SPU 行，商品层级填 “SPU”。
   - 后续每个规格生成一行 SKU 行，商品层级填 “SKU”。
   - 同一个商品的 SPU货号必须一致。
   - 每个 SKU 行必须有唯一 SKU货号。
   - SKU 行必须填写规格类型1、规格1内容。
   - 如果有第二维规格，填写规格类型2、规格2内容。

多选属性填写规则：

1. 多个风格必须拆到：风格1、风格2、风格3...
2. 多个佩戴场合必须拆到：佩戴场合1、佩戴场合2...
3. 多个营销节日必须拆到：营销节日1、营销节日2...
4. 多个主题必须拆到：主题1、主题2...
5. 不要把多个选项塞进同一个字段，除非模板字段本身就是文本说明字段。

模板公共字段：
{{COMMON_FIELDS}}

商品明细字段，必须原样返回为 headers：
{{DETAIL_HEADERS}}

字段必填说明：
{{REQUIRED_HINTS}}

当前默认值，可作为参考；不确定时可以留空，系统后续会补齐：
{{DEFAULT_VALUES}}

输出 JSON 格式必须如下：

{
  "version": "1.0",
  "source": "external_ai_temu_template",
  "sheet_name": "模版",
  "common_fields": {
    "经营站点": "",
    "发货仓": "",
    "类目": "",
    "运费模版": "",
    "承诺发货时效": "",
    "素材语言": ""
  },
  "headers": [],
  "rows": [],
  "warnings": []
}
```
